# #480 + session budget wire integration — experimental HOLD

Base: #480 head `754cab79bbe03c50bbfbe5758681dfcc2bc0e88f`. `BoundSyntheticWire` derives from the **actual** `_RealtimeWire` and supplies a budget-aware socket facade backed only by a privately created, in-memory fake. The production provider, gateway, actual credential loading and original #480 legacy raw socket paths are unchanged and hard-gated. This experiment does **not** close or remove raw paths across the real application, and is not a drop-in release. `ENABLED_SYNTHETIC`, all session budget verification flags and the live factory remain false/closed. No provider calls, credentials, production DDL or customer data are involved.

Before fake connection creation, `issue_open` consumes a committed session-wide hold; another executor cannot reopen it, including after a process dies or a coroutine is canceled after commit. The facade snapshots and serializes nested events before awaiting; while holding its sender lock, it validates operation/stage and atomically consumes its scoped budget capability and stores the SHA-256/length of the exact immutable outbound bytes before writing those bytes to the fake sink. This covers the wire's **session.update, user-level context, audio, response and allowed control frames**, including a strict ASR-off/tools-off/no-auto-response configuration. It checks the synthetic provider's config and context acknowledgement before proceeding. Context is explicitly untrusted user input. No real PCM or context is stored in the receipt table.

The suite reuses #480's existing legacy `bind_claim` shape and an always-accepting fake guard solely to exercise `_RealtimeWire`; actual session-budget response admission is independently consumed from PostgreSQL. The old guard's quote/receipt interface and the new session ledger are incompatible. **This is not proof of real user authorization, source/lease state, matching immutable model instructions, provider receipt authenticity, or parity with the production assistant.** Implement a reviewed common server-side contract before integrating the Session and gateway. The synthetic connector knows no credentials and does not exercise network open, TLS, provider behavior, real usage, audio playback, transcripts or tools.

The facade narrows the candidate composition's ordinary outbound path; it is not a process/security boundary. `_RealtimeWire`/`AiohttpRealtimeSocket` in #480 still permit raw sends on their own and other code can construct or retain a raw network socket. Python private attributes, monkey-patching and trusted in-process callers are not isolation. A releasable integration must remove those paths, ensure the only credential/network-capable process owns the socket and all billable writes, enforce role/ACL and process/network confinement, and demonstrate every configuration/context/control pathway using actual wiring. No such guarantee is claimed here.

Other blockers: no provider-enforced complete session cost maximum or verified billing bound; ASR cost disabled; expired quote must not be reused; no common source/lease/history/budget lock-order proof; no reliable remote close, cancellation/drain or reconciliation reaper after ambiguous process/DB failures; one fake connector does not prove single-owner behavior across service restarts or already-in-flight sends; missing production privileges and mixed-worker/rolling migrations; corrupted tenant reservation can cause unrelated tenant usage to undercount. Legitimate voice holds may consume the existing tenant AI cap, while generic AI code is unchanged. The local receipt schema is experimental DDL, not a production migration. The $5 budget remains unspent.

## Follow-up: expiration and synthetic snapshot binding

Admission now checks PostgreSQL `clock_timestamp()` again after waiting for tenant locks and before state changes, then checks the application clock after commit before fake socket construction/write. Tests reproduce expiry while waiting for the tenant lock and between final SQL check and COMMIT. In the latter case a receipt **can still commit after expiry**, though the synthetic pre-write check prevents the tested send; no atomic real network send and database clock/commit exist, clocks can differ, and an already-started write cannot be recalled. Do not extend the expired quote automatically or claim a hard time/provider-cost bound.

The local scope's source fingerprint is now a test-only SHA-256 of the complete scoped identity and synthetic snapshot, and the facade checks the exact approved-looking instructions and context against that pinned snapshot instead of a substring alone. This is an integrity/accidental substitution experiment, **not provenance**: its caller can construct both the snapshot and fingerprint, and neither a real source builder, authority recheck, knowledge access nor actual source epoch is connected. The source PoC's format and locking still need a reviewed unified integration. The synthetic constructor is the only way to supply this snapshot; all real access remains closed.
