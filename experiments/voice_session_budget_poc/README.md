# Session-wide budget experiment — HOLD

This is a local PostgreSQL experiment, **not a gateway, production migration, provider cost guarantee, or permission to run a paid call**. All four runtime verification flags are false. No network or secret handling is implemented. The old per-response experiment is insufficient to authorize a session: input and configuration can be sent before an individual response is claimed.

## Proposed protocol

1. A trusted server establishes authorization and binds session, tenant, actor, conversation, channel, executor, source fingerprint, model, quote, response count and ASR mode. These values are inputs to this experiment, not an authorization proof. The combined source/history/lease/budget lock hierarchy and revocation procedure are **not established**.
2. Under the shared grant row lock and tenant budget advisory lock, reserve the **entire** hypothetical session cost and a single existing tenant reservation in one committed transaction, before opening any provider connection. A local fixture uses $2.112 per response, maximum two, i.e. $4.224. `2026-11-04T00:00:00Z` is a hard expiry, not an assertion about current prices after that point. A fresh, independently verified model/rate/version/expiry is needed before any future activation. Ordinary capped AI can hit its existing cap when this legitimate hold is included; uncapped ordinary AI retains existing behavior.
3. A one-use `reserved → opening` transition, committed before a hypothetical network open, atomically changes tenant hold to `unknown`. Crash, timeout and ambiguous delivery keep the entire reservation. Reconnection is not allowed by this experiment. Before opening, cancellation may release the hold atomically; afterward it cannot.
4. The server must verify a genuine provider configuration acknowledgement before forwarding anything: exact session/model, ASR off, no tools/prompt/tracing, VAD automatic responses and idle-triggered responses off, audio/PCM 24kHz and numeric 4096 output tokens. The sample verifier only checks known fields; no real authenticated provider provenance or complete future configuration schema is established. If configuration mismatches or expires, commit `uncertain` and stop.
5. Each bounded PCM chunk consumes a durable, one-use receipt prior to send; no PCM bytes are stored. Aggregate bounds are 5,760,000 bytes and 1,200 frames, each ≤9,600 bytes. Each response has a unique, one-use claim and a separately committed dispatch transition; one or two responses draw on the **same** session hold. A trusted, authenticated completion receipt is required to admit another response. Receipt validation, a wall-clock deadline, transport-side atomicity, provider disconnect/kill and integration are not implemented. A consumed capability is never retried after an ambiguous failure.
6. Reconciliation is independent of the admission kill switch. Monotonic actual cost exceeding a matching tenant hold increases its accounted reservation and freezes voice. If the tenant hold is corrupt or belongs to another operation, preserve evidence, mark conflict, freeze voice and do not rewrite the other hold or disable unrelated AI. **Other tenant operations can undercount in this conflict case; this is unresolved and blocks use.** Never call a quarantined accounting result settled. Caller must commit freeze/uncertain results rather than rolling them back on a later exception.

## Pricing and ASR

The arithmetic is conditional on the quoted model, assumed context/output bounds and token prices: 128k input tokens × $11/1M plus 32k output × $22/1M = $2.112 per response, without assuming cache discounts. The linked pricing and platform documentation do not prove a hard provider charge ceiling per session, billing rounding, all billable events, or a remotely enforceable maximum. Even configuring a numeric response output cap and bounded input bytes does not by itself prove the provider bills at most the reservation. Input transcription is separately billable and can start on audio commit/VAD without a response. ASR (`gpt-transcribe` or otherwise) is therefore rejected before database work; published estimates do not establish a finite billable duration/rounding bound. No complete user transcript can be claimed with ASR off.

Consult current official [Realtime cost guidance](https://developers.openai.com/api/docs/guides/voice-latency-cost), [Realtime events](https://developers.openai.com/api/reference/resources/realtime/client-events/), [model documentation](https://developers.openai.com/api/docs/models/gpt-realtime-2.1-mini) and [pricing](https://developers.openai.com/api/docs/pricing) again before choosing or authorizing a future quote. A provider-confirmed upper bound or separately enforced provider-side limit that covers all charges remains necessary to assert the $5 strict cap. No paid call has been made by this experiment.

## Schema and deployment boundaries

`schema.sql` is an offline, transactional versioned expand candidate for an empty v2 legacy hold table, with legacy inserts barred after installation. It refuses unknown existing legacy history/provenance, unexpected version/constraints or an enabled grant, and checks its structural signature on rerun. Rollback of v2 is blocked while the new schema exists. No rollback that discards session evidence is supplied. The signature is not a substitute for trusted migration ownership or database ACLs. Old/new workers, existing production roles, migration runner, lock duration, row privileges, direct SQL/owner/TRUNCATE bypass and rolling deployment have not been audited. Do not run this SQL in production.

The experiment serializes its budget subset in global grant → session row → tenant spend advisory lock order, with migration schema advisory → grant/table locks. This does **not** establish an end-to-end lock order with source epochs/history and voice lease; actual paths, lock timeouts, deadlock races, role revocation, DB privileges and a safe mixed-worker cutover must be verified before integration. Ordinary generic AI code has not been changed, but legitimate voice reservations affect the existing capped ledger. A raw owner can tamper with the tables and bypass these guards. To claim a real enforcement boundary, the only network-capable gateway must be unable to bypass committed, exact-scope capabilities and must use a tested privilege model; browser credentials and direct provider access must be impossible.

## Repeat local tests

Start a disposable local PostgreSQL with a synthetic admin account. Set `VOICE_BUDGET_POC_ADMIN_URL` to its localhost `/postgres` URL. The suite rejects nonlocal hosts and inherited libpq overrides; it creates and drops only `test_voice_budget_<random>` databases. From the repo root, using Python with psycopg 3 installed:

```sh
env -i PATH="$PATH" VOICE_BUDGET_POC_ADMIN_URL="$VOICE_BUDGET_POC_ADMIN_URL" \
  PYTHONPATH="$PWD/beintaskbot-main:$PWD/experiments/voice_budget_poc:$PWD/experiments/voice_session_budget_poc" \
  python -m unittest discover -s experiments/voice_session_budget_poc -p 'test_session_budget.py' -v
```

Tests mock the disabled admission, provider receipt and config-trust flags and sometimes the database owner in their own synthetic database. These tests do not prove gateway/provider behavior, safe production privileges, billing bounds, or the missing lock hierarchy. Keep the feature disabled.
