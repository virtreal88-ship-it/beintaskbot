# BeinSystems dialogue Operator chooser rollout

This is a single-account chooser inside the existing dialogue Company picker. It is not an import, has no Operator write operations, and does not replace an existing different dialogue-company binding. Local CRM company search works independently.

- `BEINSYSTEMS_DIALOG_OPERATOR_CHOOSER_ENABLED` is off when unset. While off, the API omits `can_search_operator`, does not admit chooser requests, and leaves the existing ordinary CRM name-write behavior unchanged. The flag only applies to the exact configured `BEINSYSTEMS_OPERATOR_TENANT_ID` workspace, not to other tenants.
- The live picker is offered only to an owner with current dialogue/source and local company permissions. The owner must have a verified connected integration or a current owner-confirmed `accounts_only` credential; a configured but not connected integration is not enough. An `accounts_only` candidate is verified against the saved identity fingerprint using `/v1/user/me` before `/v1/user/accounts`. The browser receives only account identifiers, never credentials, owner identity, or unverified customer names and phone numbers.
- The environment's existing dialogue and CRM/Operator identity storage must be ready. Native/Connect WhatsApp and groups use the selected accessible source. Kommo additionally requires the separate, verified dialogue-company schema from the original rollout. An unavailable source fails closed; this patch does not provision Kommo or import/activate any account catalogue.
- Do not enable the chooser on a mix of old and new application replicas. First deploy the full reviewed revision and confirm older replicas are drained. The enabled chooser, native name writers, manual company-account associations, and existing Operator company writers use the same tenant-scoped transaction lock. Keep bulk first-batch confirmation disabled; this release does not expand its authorization.
- Activation and a production check are separate operations. Verify the disabled UI and application health first. Use a synthetic or independently authorized existing test dialogue for any future end-to-end check; do not send messages or use a real customer conversation as a test fixture. A conflict leaves the existing company and dialogue binding intact.
