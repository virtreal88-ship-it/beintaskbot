# Рабочее место оператора

Основа: production-коммит `77d5312a9b89e510a7985c2c2366a3f682e29140`.
Ветка: `codex/operator-workspace-ux`. Новых таблиц, CRM и сервисов нет.

## Ежедневная работа

В главном меню группа «Работа с клиентами» содержит «Диалоги» и «Обращения».
Владелец выдаёт сотруднику одно или оба одноимённых права в существующем редакторе сотрудников.
Доступ к редактору AI для работы оператора не требуется. Существующее право управления AI у администратора сохраняет доступ к обоим разделам.

Утром сотрудник открывает «Обращения»: по умолчанию показаны нерешённые, с приоритетом передач от AI. Есть поиск, статус, ответственный, канал и «Мои обращения». В карточке — описание, сводка, предложенные AI действия, следующий шаг, даты, ответственный и переписка.

«Взять в работу» назначает текущего сотрудника и статус «В работе». Это не изменяет AI и не отправляет сообщение. Карточка отдельно показывает эффективное состояние AI с учётом компании, агента и серверных ограничений. «Перехватить диалог» выполняет существующий handoff в Human Mode. «Открыть переписку» только читает историю; Pause/Handoff/Resume и отправка требуют отдельного действия. Решение обращения также не возобновляет AI.

«Диалоги» объединяют существующие Connect-переписки и доступный кеш переписок Kommo. Connect виден даже без CRM-сделки и без назначенного AI. Поиск работает по клиенту/номеру; фильтры — по каналу, агенту и состоянию. Счётчики показывают требующие внимания диалоги и нерешённые обращения. Длинная история и списки имеют пагинацию.

В открытом диалоге сотрудник видит канал, агента, AI-состояние, причину и ответственного; может создать обращение, остановить AI, передать человеку или явно возобновить его. Resume сохраняет существующую семантику: обрабатываются только будущие сообщения, старые не переигрываются.

## Три уровня настроек

- Компания: AI Agents → «Настройки компании». AI включён, глобальная аварийная остановка, разрешение автоотправки, лимит ответов и общие инструкции. Режим Manual/Automatic задаётся для агента; серверные флаги и лимиты API-ключа доступны только для просмотра.
- Агент: один редактор с вкладками поведения, каналов, графика, остановки/передачи, триггеров, базы знаний и черновиков. Manual/Automatic относится к конкретному агенту. База знаний использует существующую общую базу компании: интерфейс явно сообщает об этом, отдельное хранилище не создаётся.
- Диалог: только действия Pause/Handoff/Resume в выбранной переписке. Назначение обращения отделено от этих действий.

Верхняя панель AI показывает четыре отдельных факта: AI компании, Active/Test, разрешение автоотправки компании и число включённых агентов. Manual больше не изображается глобальным режимом компании. Диагностика открывается отдельной кнопкой.

Сохранение агента сохраняет существующие mode, delay, schedule, scopes и инструкции scope, в том числе настройки Nizam Ai. Изменение языка интерфейса не изменяет язык ответов агента. Новый интерфейс переведён на RU/AZ/EN и адаптирован для мобильного экрана; дополнительные фильтры сворачиваются, вкладки доступны с клавиатуры.

## Режимы агента и тестовый чат

Корпоративный Test Mode и привязки реальных тестовых диалогов удалены. Виртуальный тестовый чат использует изолированные сессии и не подключён к отправке в WhatsApp/Kommo или изменению бизнес-данных.

Manual запускает AI только по явному действию сотрудника. Automatic обрабатывает разрешённые новые обращения только при включённых настройках компании и сервера, действующем scope/расписании и отсутствии handoff, stop rules или аварийной остановки. Само назначение агента не включает автоответы.

## Минимальные точки интеграции

- `tenant_operator_access.py`: свежие права и состояние компании; `dialogs` и `support` не дают доступ к конфигурации AI. Архивированные компании запрещены.
- `tenant_operator_dialogs.py`, `tenant_operator_api.py`: только чтение существующих Connect conversations, CRM messages/deals, AI jobs/state и support tickets. Чужие tenant/channel запрещены. Kommo дополнительно ограничен доступными воронками/этапами.
- `tenant_ai_agents_store.py`: небольшой fallback авторизации для существующих conversation-state read/write; проверки провайдера, Resume и защиты от повторов сохранены.
- `tenant_chat_send_store.py`: право `dialogs` разрешает существующую отправку Connect без CRM-сделки. Проверки и транспорт Kommo остаются прежними; существующие durable receipts сохраняются.
- `tenant_support_inbox_store.py`/summary: отдельное право `support`, прежние обращения и AI-провайдер с прежними лимитами; изменены только чтение/фильтры/авторизация.

Одинаковый JID в нескольких Connect-каналах читается строго по каналу. Из-за существующего ключа AI state без channel_id управление таким неоднозначным диалогом отключено с объяснением. Это ограничение не обойдёно.

Новых worker, Connect transport, voice pipeline, Pause/Resume, handoff hooks или миграций нет. Действующий hook создания обращения при handoff остаётся в существующем backend.

## Проверки и ограничения

Автотесты используют изолированный PostgreSQL/PGlite и jsdom. AI и внешняя отправка замоканы; production не вызывается. Проверяются права, tenant/channel isolation, область воронок Kommo, назначение без изменения AI, эффективный статус, отсутствие дублей, сводка и недоступный AI, Connect без Kommo, навигация, виртуальный тестовый чат, сохранение параметров, Pause/Handoff/Resume, переписка и три языка.

Команды из каталога приложения:

```
.venv-support\Scripts\python.exe -c "import psycopg,pytest; raise SystemExit(pytest.main(['tests','-q']))"
node tests/test_tenant_operator_workspace_ui.cjs
node tests/test_tenant_support_inbox_ui.cjs
node tests/test_tenant_ai_agent_connect_scope_ui.cjs
node tests/test_tenant_ai_conversation_controls_ui.cjs
node tests/test_tenant_chat_send_ui.cjs
npm run build --prefix ui
```

Для SQL-тестов нужны `psycopg`, `pytest`, `@electric-sql/pglite`; для DOM — `jsdom` в игнорируемом `.support-test-deps`. Без этих зависимостей часть тестов пропускается. Локально они установлены и SQL/DOM проверки выполнялись.

В браузере проверены меню, очередь и редактор на 390×844, а также desktop. Использовались синтетические данные. Реальный WhatsApp/AI smoke-test необходимо выполнить в разрешённой тестовой компании перед выкладкой. Загрузка файлов из нового Connect composer скрыта: существующий upload API рассчитан на Kommo; текстовая отправка использует действующий Connect путь.

Для Astra при объединении: проверить conversation-state fallback рядом с последними Pause/Resume-изменениями; read-only проекцию voice-сообщений и времени последнего сообщения; скрипты/DOM id и пересобранный `tenant-chakra-ui.js`; Manual вызов AI без отправки, а разрешённый Automatic send — на тестовом Connect-канале. Известного блокирующего дефекта, требующего переписывания worker/voice, не выявлено.
