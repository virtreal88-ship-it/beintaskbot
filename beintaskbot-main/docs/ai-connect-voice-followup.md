# Задача для Astra / GPT-6 High: безопасная обработка голосовых сообщений Connect

## Контекст

Connect корректно распознаёт входящее голосовое WhatsApp-сообщение как `audio`, но
сейчас передаёт в Beintaskbot только тип сообщения, без безопасной ссылки или байтов
медиа. Поэтому агент не должен угадывать содержание аудио: оно отражается в истории
как недоступное вложение. Голосовые ответы в Connect также пока не поддерживаются.

Это не должно блокировать текстовые сообщения, но полноценная расшифровка требует
отдельной, тщательно проверенной реализации. Не добавлять голосовой ответ в рамках
этой задачи.

## Цель

Дать AI Agents возможность безопасно получить расшифровку разрешённого входящего
голосового сообщения Connect, сохранив tenant isolation, идемпотентность и текущую
защиту медиа.

## Границы реализации

1. Проверить документированный контракт deployed Evolution API для получения медиа
   конкретного сообщения. Не извлекать URL/ключи из сырых webhook-полей и не
   публиковать сессионные URL.
2. В Connect сохранять только tenant/channel-bound opaque reference и минимальные
   MIME/размер/идентификатор сообщения. Не раскрывать данные между компаниями.
3. Сделать HMAC-аутентифицированный внутренний одноразовый resolver либо bounded
   streaming endpoint между Beintaskbot и Connect. Он должен проверять tenant,
   channel и message id до запроса к Evolution.
4. В Beintaskbot переиспользовать существующие проверки MIME-типа, размера,
   ограничения сети и транскрибацию, но получать поток только через resolver.
   Не принимать произвольные клиентские URL.
5. Кешировать результат транскрибации только в пределах tenant-а; повтор webhook
   не должен повторно списывать токены или создавать вторую AI-задачу.
6. Ошибка, неподдерживаемый MIME, истёкший reference или слишком большой файл должны
   сохраняться как безопасная диагностика сообщения и никогда не блокировать
   последующий текст в этом диалоге.
7. Сроки хранения, удаление и аудит медиа должны быть явными. Не логировать
   содержимое аудио, ключи, подписанные URL или секреты.

## Обязательные проверки

- успешная расшифровка voice message;
- повтор того же события не вызывает вторую расшифровку;
- неверный tenant/channel/message id отклоняется;
- просроченный, неподдерживаемый и слишком большой файл изолированно завершаются;
- последовательность «текст → голосовое с ошибкой → текст» продолжает обработку
  второго текста;
- Human Mode/пауза, Test Mode и final send lock продолжают работать;
- отсутствует исходящая голосовая отправка, пока она отдельно не согласована.

## Вне объёма

- голосовые ответы;
- новый Railway-сервис;
- изменение настроек существующих агентов, моделей или ключей;
- массовая повторная обработка старых сообщений.
