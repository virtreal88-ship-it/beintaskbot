# Сценарий браузерного E2E для AI Agents в `/app`

Проверка проводится только на staging tenant с отдельной тестовой PostgreSQL, тестовой Kommo-интеграцией и специально созданным внутренним чатом. Не используйте реальные контакты, клиентские каналы или production OAuth. Серверные `AI_AGENTS_AUTO_SEND_ENABLED` и `AI_AGENTS_CRM_ENABLED` должны быть `false`.

## Подготовка

1. Создайте тестовую компанию и пользователя с ролью владельца. Подключите только staging Kommo и существующий Chat AI; включите Chat AI и согласие на отправку данных провайдеру. Включите обработку аудио только для аудио-сценария.
2. Создайте внутренний тестовый чат в тестовом pipeline/stage. Сохраните его pipeline ID, stage ID, Talk ID, Chat ID и тестовый канал.
3. Запустите приложение на staging URL и откройте `/app` в Chromium. Не используйте `/webapp` как замену этому сценарию.
4. Подготовьте приложение Playwright в тестовом окружении (`npm install --save-dev @playwright/test`, `npx playwright install chromium`) и настройте `BASE_URL`, `TEST_LOGIN`/сессию владельца и идентификаторы тестового чата через секреты окружения. Не помещайте токены в исходный код или отчёт.

## Основной сценарий

1. Войти владельцем, открыть AI Agents и проверить, что экран и его запросы загружаются без ошибок. Повторить вход пользователем без `ai_agents_manage`: UI не должен показывать управление, а прямой запрос на изменение должен вернуть `403`.
2. Включить AI Agents для тестовой компании, убедиться, что автоматическая отправка и CRM-действия выключены. Создать агент `E2E manual`, оставить режим Manual, задать scope из тестовых pipeline/stage/channel и включить агента.
3. Добавить короткую тестовую базу знаний, например `График тестовой компании: 10:00–18:00`, сохранить, обновить страницу и проверить, что источник сохранился. Создать phrase-trigger для безвредной фразы `e2e trigger phrase`, включить только разрешённое действие `handoff` либо оставить список действий пустым.
4. Закрыть все вкладки `/app` и отправить в Kommo внутреннего тестового чата искусственное сообщение `Какие часы работы?`. Подождать минимум 40 секунд. Ожидаемый результат: webhook поставил событие в очередь, worker создал draft, хотя ни один сотрудник не открывал `/app`; никаких исходящих сообщений в чате нет.
5. Открыть `/app` снова и найти draft тестового агента. Проверить текст по тестовой базе знаний, исходные Talk/Chat/message ID и статус Manual. Повторная доставка того же webhook не должна создать второй draft.
6. Пока генерируется следующий тестовый draft, отправить второе сообщение от менеджера в тот же тестовый чат. Ожидаемый результат: устаревший ответ помечен superseded/не отображается как актуальный; очередь не отправляет сообщение.
7. Запустить тест без разрешения AI Agents у пользователя и с чужим tenant ID в теле API-запроса. Ожидаемый результат: запрет доступа/конфликт tenant, данные соседней тестовой компании не видны.

## Аудио и изображение

Для двух отдельных сообщений использовать синтетический звук и изображение без персональных данных, отправленные только в тестовый чат. Для аудио включить в существующих Chat AI настройках `audio_enabled`, дождаться worker и проверить, что транскрипция отражена в draft. Для изображения отправить файл с простым однозначным содержимым и вопросом о нём; проверить, что ответ учитывает изображение. Проверить worker/run-логи и статус вложения: если ссылка истекла, формат не поддержан или vision-модель отвергла запрос, агент должен обозначить вложение как необработанное и не создавать ответ, выдающий догадку за анализ.

## Негативные сценарии и критерии завершения

- Повторно доставить событие, создать параллельную обработку двух worker и проверить уникальность/`SKIP LOCKED` интеграционным скриптом `tests/postgres/verify_ai_agents.py`.
- Смоделировать ошибку загрузки медиа и неподдерживаемый MIME на тестовом окружении. Запрос не должен отправлять вложение третьему домену; ответ не должен утверждать, что вложение изучено.
- Обновить страницу, проверить отсутствие ошибок в Console/Network для `/assets/tenant-ai-agents.js` и `/api/platform/ai/agents/*`; проверить корректные empty/error/loading states.
- В течение всей проверки в тестовом чате не должно появиться ни одного исходящего сообщения от агента. После проверки выключить агента и AI Agents в staging компании.

Перед запуском E2E подготовьте тестовую компанию и каналы, не загружайте клиентские данные. Этот сценарий проверяет UI и автономный worker; он не является разрешением на пилот в production.
