# Библиотека шаблонов AI Agents

Ветка создаётся отдельно от `origin/main` (`9f3bf628`). Только `/app`; runtime, изоляция каналов, backend создания, storage знаний, `/webapp` и Railway не меняются.

## Структура

`tenant-agent-catalog.js` — реестр четырёх категорий и реализованных шаблонов, проверка согласованного каталога подключений, преобразование UI-выбора в существующие scopes. Категории: техническая поддержка, продажи, обслуживание клиентов, автоматизация процессов. Категории добавляются в реестр; новые кнопки верхней панели не нужны.

`tenant-agent-library.js` и `tenant-agent-library.css` — библиотека в существующем модальном дизайне: «Создать с нуля», категории, фильтр WhatsApp/Kommo CRM и карточки. В других категориях пока нет шаблонов. Не реализованные варианты (`ready:false`) не публикуются. Реализованный шаблон нельзя запустить без пригодного подключения и разрешённой модели.

Первый шаблон — **«Оператор технической поддержки»**. Инструкции: ответы по базе знаний, уточнение проблемы, запрет выдуманных решений и результатов, передача сложных/нерешённых проблем сотруднику через существующий handoff. Ночной режим больше не является типом агента: в общем шаге расписания можно задать 19:00–09:00, 22:00–06:00 или дневной интервал. Начальные часы шаблона — Пн–Пт 09:00–18:00.

`tenant-night-agent-template.js` остаётся прежним идемпотентным мастером с общими шагами для шаблона и создания с нуля. Старые filename/DOM IDs/API-имена оставлены для совместимости; отдельная кнопка «Ночной оператор» больше не вставляется в header. Существующие созданные агенты не переименовываются и не перенастраиваются автоматически.

Создание с нуля начинает с пустых имени, инструкций и дополнительных handoff-фраз; знания необязательны, расписание можно включить. После создания кнопка открывает существующий редактор конкретного агента для знаний, условий остановки, всех типов триггеров и остальных настроек. Для техподдержки файл знаний нужен, если общих активных знаний ещё нет.

## Безопасные значения и повтор

Новый агент создаётся `enabled:false`, по умолчанию `mode:manual`, без выбранных подключений и с `allow_group_messages:false`. Automatic выбирается пользователем отдельно. Включение требует отдельного явного подтверждения; PATCH enabled выполняется после успешных шагов мастера. Company Active/Test Mode и автоотправка никогда не переключаются мастером. Human Mode, Pause и аварийная остановка остаются в существующем runtime.

До первого POST сохраняются непрозрачный `setup_key` и снимок конфигурации в локальном хранилище, раздельно по tenant, сотруднику и варианту создания. После возможной отправки снимок фиксируется. Повтор всегда использует существующий POST agents с тем же ключом: ID возвращается сервером, а не берётся на доверии из localStorage. Триггер и knowledge upload также используют прежние ключи. Это покрывает потерю ответа **до получения ID агента**, перезагрузку страницы, частично завершённые шаги и потерянный ответ загрузки.

Сохраняются конфигурация, ID и метаданные файла, но не байты файла и не ключи AI. После перезагрузки незавершённый файл нужно выбрать повторно. Если localStorage недоступен, новый POST не выполняется. Старые незавершённые записи night wizard v1 поддерживаются без смены ID и повторной загрузки уже подтверждённых знаний. Очистка пользователем localStorage лишает мастер локального ключа восстановления; намеренное новое создание является новым агентом.

После постороннего изменения конфигурации ранее созданного агента мастер предлагает редактор и не добавляет триггеры, знания или активацию по устаревшему снимку. При закрытии или смене компании поздний ответ не запускает следующие шаги/активацию. Идемпотентный POST позволяет безопасно продолжить позже. Все JSON/multipart mutations несут `expected_tenant_id` и `expected_user_id`; backend повторно проверяет текущие права, tenant и scope.

## API и контракт Astra

Новый backend создания не добавляется. Используются:

- `GET /api/platform/me` — текущая компания/сотрудник/права.
- **`GET /api/platform/ai/channels?expected_tenant_id=…&expected_user_id=…`** — согласованный с Astra каталог `schema_version:1`.
- `GET /api/platform/ai/agents/options?cached=1` — разрешённые модели, воронки/этапы Kommo. Старый `connect_channels` не используется как fallback каталога.
- `GET /api/platform/ai/agents/settings` — только чтение общих ограничений и режима.
- `GET /api/platform/ai/knowledge` — доступные общие активные знания.
- `POST /api/platform/ai/agents` — существующее идемпотентное создание выключенного агента.
- `POST /api/platform/ai/agents/{id}/triggers` — существующий handoff, если задан.
- `POST /api/platform/ai/knowledge/upload` — существующая загрузка; обязательный `agent_id` созданного агента, прежний `setup_key`.
- `PATCH /api/platform/ai/agents/{id}` — только явно подтверждённая активация с `expected_version`.

Для карточки подключения используются `provider`, `type`, `name`, `connection.state`, `ai.supported`, `ai.available`, `capabilities.text_replies`, `scope`. `id=provider:channel_id` — только ключ checkbox/UI; он никогда не записывается как runtime channel_id. Scope получает исходные `scope.provider`/`scope.channel_id`. Доступно только `supported && available && text_replies`. Connect с неподдерживаемым типом, неизвестные провайдеры и некорректные scope/ID не становятся вариантами выбора. Нет поддержки Instagram/Telegram, определения типа по названию или доступа ко всем каналам.

Название: «WhatsApp — Основной номер», «WhatsApp — Техническая поддержка» или «Kommo CRM — Канал CRM». Ниже отдельно показаны сохранённое состояние, интеграция Connect/Kommo и допуск AI. Connect не представлен самостоятельным пользовательским каналом. Несколько выбранных подключений дают по одному точному scope. Для выбранных Kommo-каналов обязательны явные pipeline_id и stage_id из tenant-owned options; мастер использует одну выбранную пару для этих каналов. Более сложные сочетания настраиваются в существующем редакторе.

Astra подтвердил: `ai.available` означает пригодность подключения для конфигурации и не зависит от включения AI компании или Manual/Automatic. Это не гарантия ответа: права, модель, квоты, расписание, Test Mode, Human Mode и exact dialogue/Talk route проверяются runtime. Для Kommo допустим `connection.state:unknown` при доступной CRM и доказанном tenant-owned канале — UI не изображает его живое подключение подтверждённым. Для Connect сохранённый неизвестный/отключённый статус не допускается. Поддерживаются connected, disconnected, connecting, pending_qr, reconnecting, reconnect_required, error, disabled, unknown.

**Зависимость интеграции:** маршрут channels v1 реализован Astra в `codex/channel-catalog-ai-state`, коммит `2d58fd0daff396f1d68b517826669e07451a97b2`; согласованный документ — `docs/ai-channel-state-contract.md` в этой ветке. Поля и семантика сверены с итоговой реализацией каталога. Его нет в базовом `main 9f3bf628`. Без этого маршрута, при неверной версии схемы или ошибке каталога библиотека показывает объяснение и блокирует создание; неподтверждённый старый список не подставляется. UI контракт проверен тестовыми ответами v1, backend создания — настоящими изолированными PostgreSQL-тестами. Реальные tenant/Connect/Kommo не использовались.

## Интеграция Terra

Верхняя панель и её разметка/стили не изменены. Удалена только прежняя вставка `aiNightTemplateQuick` из самого мастера. Для существующих `[data-ai-overview-create]` и `#aiNewAgent` библиотека перехватывает действие создания, не добавляя buttons в header. Новый header Terra может вместо привязки к этим селекторам вызвать `window.tenantAgentLibrary.open()` или отправить `tenant-ai-create-request`.

Порядок assets: существующий AI Agents console → night l10n → agent catalog → существующий wizard → agent library. Три новых assets зарегистрированы `no-store`. Завершение отправляет `tenant-ai-agent-created` для обновления списка. `tenant-ai-edit-created-agent` с `{agentId}` открывает существующий редактор после tenant-scoped GET agents. Эти два обработчика — единственные добавления в `tenant-ai-agents.js`; header не редактируется.

При объединении сохранить additions обоих авторов в `tenant_web_assets.py`, `docs/tenant-app.html` и тесте точного каталога routes/assets. Не возвращать legacy-кнопку ночного оператора. Проверить один запуск библиотеки на click, каталог v1, отсутствие default selected channels, Unknown Kommo state, backend-rejection чужого/неактивного канала, ночное расписание, потерю ответа POST/upload, RU/AZ/EN, смену компании и явную активацию в staging.
